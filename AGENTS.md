# Работа с Radial New Tab

- Отвечай по-русски; основная среда — Windows 11. Коммиты — Conventional Commits на русском языке.
- Для задач разработки запускай `pnpm check`, `pnpm test`; для пользовательских изменений также `pnpm package` и `pnpm test:ui`. Для изменений только скриптов публикации достаточно проверки типов/lint и модульных тестов публикации.

## Каналы управления выпуском

Публикация пакета и проверка операций выполняются через Microsoft Publish API из GitHub Actions. Секрет остаётся в GitHub Actions: не запрашивай его в чате, не записывай в исходники и не печатай заголовки запросов.

1. Проверить доступ без изменения текущей отправки:
   `gh workflow run edge-api-check.yml --ref main`
2. Получить статус известной операции:
   `gh workflow run edge-api-check.yml --ref main -f operation_id=UUID -f stage=submission`
   Для операции загрузки использовать `-f stage=upload`.
3. Проверить результат через GitHub MCP (workflow runs/jobs/artifacts) или `gh run list`, `gh run view`, `gh run download`. Artifact — `edge-api-check`.
4. Новый обычный GitHub Release с тегом `v` + версия запускает проверки, проверку доступа API, загрузку ZIP и отправку на сертификацию. Успешный запрос отправки не означает одобрение магазина. Operation ID сохраняются в artifact `edge-publication-status`.

Доступ проверен 16 ноября 2026 года; секрет уже настроен в GitHub Actions, срок ключа — 27 января 2027 года. Перед задачей проверяй реальный workflow, не проси пользователя заново создавать ключ или включать доступ к файлам без фактической ошибки. При необходимости обновления ключа используй кнопку копирования на странице и `scripts/set-edge-api-key.ps1`; не выводи полный AX/DOM снимок страницы с раскрытым ключом и не полагайся на регулярное выражение для его маскирования.

Если подходящий GitHub MCP поддерживает нужную операцию, используй его. Если dispatch/release недоступны в подключённом MCP, используй авторизованный `gh` — он обращается к тому же GitHub API. Не создавай новый релиз для одной проверки доступа.

## Карточка магазина через браузерный MCP

Microsoft не предоставляет публичного Publish API для описаний и изображений. Используй браузерный MCP (`cua_repl`) и существующую сессию Edge в Partner Center. Доступ ChatGPT к URL файлов уже включён пользователем; сначала пробуй штатный file chooser, не проси включать его повторно без фактической ошибки.

- Продукт: `5461df96-61e7-440c-9d48-1f967336caa2`.
- Кабинет: `https://partner.microsoft.com/en-us/dashboard/microsoftedge/5461df96-61e7-440c-9d48-1f967336caa2/packages/dashboard`.
- API-ключи: `https://partner.microsoft.com/en-us/dashboard/microsoftedge/publishapi`. Английская локализация предпочтительна: в русской замечен пустой диалог продления ключа.
- Тексты: `docs/edge-store/listing-ru.txt`, `listing-en.txt`; изображения — рядом. После обновления сохранить оба описания, применить изображения к обоим языкам и проверить конечный статус отправки.
- Не использовать скрытые внутренние HTTP endpoints Partner Center и не извлекать cookies. Для продления ключа соблюдать требования инструмента к изменению учётных данных. Детали — `docs/RELEASE_AUTOMATION.md`.

При HTTP 401 проверить срок ключа и GitHub Secrets. При 403 проверить Client ID и доступ к продукту. При 404 в проверке доступа сверить operation ID: старую операцию могли удалить. Не повторять POST автоматически после таймаута или неизвестного результата: сначала прочитать записанную операцию или состояние кабинета.

Версия 0.3.1 уже отправлена через кабинет и находится на проверке. Не перезапускать её неудачный workflow публикации ради проверки нового ключа.
